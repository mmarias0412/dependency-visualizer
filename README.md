# dependency-visualizer

Инструмент визуализации графа зависимостей npm-пакетов
(практическая работа, вариант 22). Готовые менеджеры пакетов и
библиотеки для получения зависимостей не используются. Только
стандартная библиотека Python 3.9+.

Реализованы этапы:

1. Минимальный прототип с конфигурацией (CLI).
2. Сбор данных о прямых зависимостях пакета.
3. Построение графа зависимостей с учётом транзитивности.

## Параметры

| Опция | Описание | По умолчанию |
|-------|----------|--------------|
| `-p`, `--package` | имя анализируемого пакета (обязательно) | — |
| `-r`, `--repo` | URL репозитория или путь к файлу тестового репозитория | `https://registry.npmjs.org` (в тестовом режиме обязателен) |
| `-t`, `--test-mode` | режим работы с тестовым репозиторием | выключен |
| `-d`, `--max-depth` | максимальная глубина анализа (1–100) | `3` |
| `-f`, `--filter` | подстрока: пакеты с ней в имени не учитываются | пусто |

## Этап 1. Конфигурация

Приложение принимает параметры из командной строки и проверяет их.
На этом этапе проверенные параметры выводились в формате
«ключ: значение»; начиная с этапа 2 вывод заменён результатами работы.

Проверяются:

- имя пакета: правила npm (в тестовом режиме — заглавные латинские буквы);
- URL репозитория: должен начинаться с `http://` или `https://`;
- файл тестового репозитория: должен существовать и быть доступен для чтения;
- глубина анализа: целое число от 1 до 100;
- подстрока фильтра: без пробельных символов и не содержится в имени
  анализируемого пакета.

При ошибке выводится сообщение `depviz: error: ...`, код возврата 2.

## Этап 2. Сбор данных

Для пакета запрашивается описание его последней версии
(`<repo>/<package>/latest`), из поля `dependencies` берутся прямые
зависимости. Для пакетов с областью имён (`@babel/core`) символ `/` в
адресе кодируется как `%2F`.

Ошибки получения данных (пакет не найден, репозиторий недоступен, ответ
не в формате JSON или без версии, ошибка в файле тестового
репозитория) выводятся как `depviz: error: ...`, код возврата 1.

## Этап 3. Граф зависимостей

Граф строится обходом в ширину, реализованным рекурсивно: функция
обрабатывает один уровень пакетов и рекурсивно вызывает себя для
следующего уровня. Каждый пакет запрашивается один раз.

- **Глубина** (`-d`). Корневой пакет находится на глубине 0. Пакеты на
  глубине `-d` попадают в граф, но не раскрываются (их зависимости не
  запрашиваются) и помечаются `(depth limit)`. При `-d 1` выводятся
  только прямые зависимости.
- **Фильтр** (`-f`). Пакет, в имени которого есть подстрока (регистр
  учитывается), не попадает в граф, а его зависимости не
  просматриваются. Если подстрока содержится в имени самого
  анализируемого пакета, выдаётся ошибка.
- **Циклы.** Уже встреченный пакет повторно не раскрывается, поэтому
  цикл не приводит к бесконечному обходу. Ребро в уже встреченный пакет
  остаётся в графе; для каждого обратного ребра выводится один найденный
  цикл (`Cycle: A -> B -> A`). Для пакета, зависящего от самого себя,
  выводится `Cycle: A -> A`.
- **Версии.** Для каждой зависимости берётся последняя версия пакета,
  а диапазоны версий (`^1.2.0` и т. п.) не разрешаются. Поэтому граф
  может отличаться от того, что установит npm.

Формат вывода: строка `пакет: зависимости` для каждого пакета в
порядке обхода в ширину, затем число пакетов и найденные циклы.
Зависимости перечисляются в алфавитном порядке, `-` означает «нет
зависимостей».

### Тестовый репозиторий

Режим `-t` читает граф из файла вместо реального репозитория. В файле
одна строка на пакет: `ИМЯ: ЗАВИСИМОСТЬ ЗАВИСИМОСТЬ ...`. Имена
пакетов — заглавные латинские буквы, зависимости разделяются пробелами
или запятыми, пустые строки и текст после `#` игнорируются. Пакет можно
описать только один раз; пакет, упомянутый только как зависимость,
считается пакетом без зависимостей. Анализируемый пакет должен быть
описан в файле.

В папке `examples/` лежат файлы для демонстрации:

| Файл | Случай |
|------|--------|
| `diamond.txt` | общая зависимость (ромб) |
| `cycle.txt` | цикл `A -> B -> C -> A` |
| `chain.txt` | цепочка для проверки глубины |
| `large.txt` | граф побольше: общие пакеты, цикл через корень, недостижимые пакеты |

## Структура проекта

```
src/
  main.py       точка входа
  cli.py        параметры командной строки, запуск
  config.py     проверка параметров, фильтр
  errors.py     общий тип ошибок репозитория
  registry.py   получение зависимостей из npm-реестра
  file_repo.py  чтение тестового репозитория из файла
  graph.py      построение графа (рекурсивный BFS), поиск циклов
  report.py     текстовый вывод графа
tests/
  helpers.py          запуск CLI, тестовый HTTP-сервер вместо реестра
  test_cli.py         проверка параметров
  test_registry.py    реестр и граф по данным реестра
  test_graph.py       BFS, глубина, фильтр, циклы
  test_file_repo.py   чтение тестового репозитория
  test_scenarios.py   сценарии на файлах из examples/
examples/             тестовые репозитории
run.bat, run.sh       скрипты запуска
```

## Сборка и тесты

Сборка не требуется. Запуск тестов из корня проекта.

PowerShell:

```
$env:PYTHONPATH="src"; python -m unittest discover -s tests -v
```

cmd:

```
set PYTHONPATH=src
python -m unittest discover -s tests -v
```

Linux/macOS:

```
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

## Примеры использования

Реальный репозиторий (на каждый пакет делается отдельный запрос, при
большой глубине работа может занять заметное время):

```
python src/main.py -p express -d 1
python src/main.py -p debug -d 2 -f types
```

Тестовый репозиторий:

```
python src/main.py -p A -t -r examples/diamond.txt -d 5
python src/main.py -p A -t -r examples/cycle.txt
python src/main.py -p A -t -r examples/chain.txt -d 2
python src/main.py -p A -t -r examples/large.txt -d 5 -f F
```

Пример вывода для `examples/cycle.txt`:

```
Dependency graph of A (max depth 3):
A: B
B: C
C: A
Packages: 3
Cycle: A -> B -> C -> A
```

Либо через скрипты: `run.bat -p A -t -r examples/cycle.txt` (Windows),
`./run.sh -p A -t -r examples/cycle.txt` (Linux/macOS).
