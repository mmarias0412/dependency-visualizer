# dependency-visualizer

Инструмент визуализации графа зависимостей npm-пакетов
(практическая работа, вариант 22). Готовые менеджеры пакетов и
библиотеки для получения зависимостей не используются.

Реализован **этап 1** — минимальный CLI-прототип с конфигурацией.

## Общее описание

Приложение принимает параметры из командной строки, проверяет их и
выводит в формате «ключ: значение». Только стандартная библиотека
Python 3.9+.

## Параметры

| Опция | Описание | По умолчанию |
|-------|----------|--------------|
| `-p`, `--package` | имя анализируемого пакета (обязательно) | — |
| `-r`, `--repo` | URL репозитория или путь к файлу тестового репозитория | `https://registry.npmjs.org` (в тестовом режиме обязателен) |
| `-t`, `--test-mode` | режим работы с тестовым репозиторием | выключен |
| `-d`, `--max-depth` | максимальная глубина анализа (1–100) | `3` |
| `-f`, `--filter` | подстрока: пакеты с ней в имени пропускаются | пусто |

В тестовом режиме имена пакетов — заглавные латинские буквы (`A`, `B`),
а `--repo` — путь к существующему файлу.

## Ошибки

Некорректное имя пакета, URL без `http(s)://`, несуществующий файл
тестового репозитория, глубина не целая или вне диапазона, пробелы в
подстроке — сообщение `depviz: error: ...` и код возврата 2.

## Сборка и тесты

Сборка не требуется. Запуск тестов (из корня проекта):

```
set PYTHONPATH=src
python -m unittest discover -s tests -v
```

## Примеры использования

```
python src/main.py -p express -d 2 -f types
python src/main.py -p A -r README.md -t -d 5
```

Либо через скрипты: `run.bat -p express` (Windows),
`./run.sh -p express` (Linux/macOS).
