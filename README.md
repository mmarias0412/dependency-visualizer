# dependency-visualizer

Инструмент визуализации графа зависимостей npm-пакетов
(практическая работа, вариант 22). Готовые менеджеры пакетов и
библиотеки для получения зависимостей не используются. Только
стандартная библиотека Python 3.9+.

Реализованы этапы:

1. Минимальный прототип с конфигурацией (CLI).
2. Сбор данных о прямых зависимостях пакета.

## Параметры

| Опция | Описание | По умолчанию |
|-------|----------|--------------|
| `-p`, `--package` | имя анализируемого пакета (обязательно) | — |
| `-r`, `--repo` | URL репозитория или путь к файлу тестового репозитория | `https://registry.npmjs.org` (в тестовом режиме обязателен) |
| `-t`, `--test-mode` | режим работы с тестовым репозиторием (пока не поддерживается) | выключен |
| `-d`, `--max-depth` | максимальная глубина анализа (1–100), используется с этапа 3 | `3` |
| `-f`, `--filter` | подстрока: пакеты с ней в имени пропускаются, используется с этапа 3 | пусто |

В тестовом режиме имена пакетов — заглавные латинские буквы (`A`, `B`),
а `--repo` — путь к существующему файлу.

## Этап 1. Конфигурация

Приложение принимает параметры из командной строки и проверяет их.
На этом этапе проверенные параметры выводились в формате
«ключ: значение»; начиная с этапа 2 вместо этого выводятся результаты
сбора данных.

Проверяются:

- имя пакета: правила npm (в тестовом режиме — заглавные латинские буквы);
- URL репозитория: должен начинаться с `http://` или `https://`;
- файл тестового репозитория: должен существовать и быть доступен для чтения;
- глубина анализа: целое число от 1 до 100;
- подстрока фильтра: без пробельных символов.

При ошибке выводится сообщение `depviz: error: ...`, код возврата 2.

## Этап 2. Сбор данных

Приложение запрашивает у npm-реестра описание последней версии пакета
(`<repo>/<package>/latest`) и выводит его прямые зависимости (поле
`dependencies`) вместе с допустимыми диапазонами версий в алфавитном
порядке. Для пакетов с областью имён (`@babel/core`) символ `/` в
адресе кодируется как `%2F`.

Пример вывода:

```
Direct dependencies of express@5.3.0:
  accepts: ^2.0.0
  body-parser: ^2.3.0
  ...
```

Если у пакета нет зависимостей, выводится
`Direct dependencies of <пакет>@<версия>: none`.

Ошибки получения данных (пакет не найден, репозиторий недоступен,
ответ не в формате JSON или без версии, тестовый режим) выводятся как
`depviz: error: ...`, код возврата 1.

## Структура проекта

```
src/
  main.py       точка входа
  cli.py        параметры командной строки, вывод результата
  config.py     проверка параметров
  registry.py   получение зависимостей из реестра
tests/
  helpers.py        запуск CLI и тестовый HTTP-сервер вместо реестра
  test_cli.py       тесты проверки параметров
  test_registry.py  тесты сбора данных
run.bat, run.sh     скрипты запуска
```

## Сборка и тесты

Сборка не требуется. Запуск тестов из корня проекта.

PowerShell:

```
$env:PYTHONPATH="src"; python -m unittest discover -s tests -v
```

cmd:

```
set PYTHONPATH=src
python -m unittest discover -s tests -v
```

Linux/macOS:

```
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

## Примеры использования

```
python src/main.py -p express
python src/main.py -p @babel/core -r https://registry.npmjs.org
python src/main.py -p express -d 0
```

Последняя команда выведет `depviz: error: max depth must be between 1
and 100, got 0`.

Либо через скрипты: `run.bat -p express` (Windows),
`./run.sh -p express` (Linux/macOS).
